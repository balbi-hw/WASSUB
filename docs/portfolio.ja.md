# WASSUB | SSAFY向けチームワークスペース

[한국어판](./portfolio.md)

WASSUBは、GitLab、Jira、Notion、Mattermost、Jenkinsに分散したチームの作業情報を一つの画面で確認できるWebサービスです。GitLabのプロジェクトを基にワークスペースを作成し、ダッシュボードで課題、マージリクエスト（MR）、文書、お知らせ、ビルド状況を確認してから、必要な作業へ進めます。

> この文書は、元のプロジェクトリポジトリの実装とデモ手順を基にサービスの流れをまとめたポートフォリオです。企画段階のMVP目標をすべて実装済みの機能として扱ってはいません。以下の画像は実際のフロントエンドをローカルで起動して撮影しました。ログイン画面以外のデータはデモ用APIレスポンスであり、実サービスの連携結果や運用成果を示すものではありません。

> 実装資料へのリンクは元のGitLabリポジトリを指しており、閲覧に権限が必要な場合があります。

## 1. サービス全体の流れ

| 段階 | ユーザーが行うこと | システム側の処理 |
|---|---|---|
| ログイン・初期設定 | GitLabでログインし、参加するプロジェクトを選ぶ | OAuth認証、プロジェクトの検索、ワークスペースの作成・参加 |
| ツール連携 | Jira、Notion、Jenkinsなどをチームに接続する | 権限の確認、外部トークンとWebhook設定の管理 |
| ダッシュボード | 課題、MR、文書、お知らせ、ビルド状況を確認する | 外部APIの結果と保存済みイベントをウィジェットに反映 |
| 詳細確認 | 項目の詳細や元のツールを開く | 必要な情報をサービス内に表示し、元ページへのリンクを提供 |
| リアルタイム更新 | MR、ビルド、お知らせの変更を画面で確認する | Webhook受信後、ワークスペースごとにSSEイベントを配信 |
| 運用状況の確認 | EC2のリソースとコンテナの状態を見る | Goエージェントが定期的にメトリクスを収集・送信 |

### GitLabプロジェクトからワークスペースを作るまで

1. GitLab OAuthログイン後、まだワークスペースに参加していないユーザーに、プロジェクト検索用の一時的なsetup ticketを発行します。
2. プロジェクトを選ぶと、サーバーがMaintainer権限とプロジェクトの状態を再確認します。
3. ワークスペースの作成時にGitLab Project Access Tokenを発行し、ダッシュボードのデータ取得に使用します。
4. 同じプロジェクトのほかのメンバーは参加候補として登録され、ログイン後に自分で参加します。候補に入っただけでは自動参加しません。

プロジェクト検索に使う個人のOAuthトークンと、チームのダッシュボードに使うワークスペースのトークンを分けた設計です。ワークスペース作成の処理

## 2. 主な機能 — チームダッシュボード

![WASSUBの統合ダッシュボード](./assets/screenshots/wassub-dashboard.jpg)

*ローカルで起動した画面・Jiraのカンバン、GitLabのMR、Notionのショートカット（デモ用データ）*

| 領域 | 画面でできること | 実装・設計資料 |
|---|---|---|
| Jira | スプリントの進捗、カンバン、期限が近い課題を確認し、課題のステータスを変更 | Jiraのフロントエンド、Jira連携 |
| GitLab | オープン中のMR、レビュー待ち、コミットとリポジトリ情報を確認 | GitLabダッシュボード |
| Notion | チーム共通の重要ページと個人のお気に入りを登録・閲覧し、ページの詳細を確認 | Notion連携 |
| Mattermost | 全体・クラス別のお知らせとAIによる要約を確認 | お知らせ分析 |
| Jenkins | ジョブ、ビルド結果、失敗ログの分析結果を確認 | Jenkins連携 |

ダッシュボードは、各ツールにある情報を集めて現在の状況を把握するための入口です。GitLabの取得APIではワークスペースへの参加状態とトークンの状態を確認し、JiraやNotionなどの接続状態はツールごとに管理します。ウィジェットの項目は、可能な場合は元のツールの詳細ページへつなぎます。

### 変更を画面に届ける経路

```text
GitLab・Jenkins・MattermostのWebhook
                  ↓
        Spring Bootが受信・検証
                  ↓
      保存・ワークスペースイベント
                  ↓
             SSE → Web画面
```

Jenkinsのビルド状況はWebhookで即時に通知し、コミットのステータスはGitLabにも記録して再取得できるようにしました。画面がイベントを受け取れなかった場合も、保存済みの状態と外部ツールから現在の情報を確認できる構成です。SSEの設計、Jenkins連携

## 3. 主な機能 — AIによる作業支援

### MRの事前レビュー

GitLabのMR Webhookを受け取ったSpringサーバーが、FastAPIにレビューのジョブを登録します。AIサービスのワーカーは待機中のジョブを取得した後、必要なGitLabの認証情報をSpringサーバーから受け取り、MRの変更内容を分析します。結果はSpringへコールバックし、GitLabへのコメント投稿とダッシュボードへの反映はSpringが担当します。ジョブの受付とレビューの完了は別々の状態として扱います。MRレビューの実装資料

### ビルドログとお知らせの分析

- Jenkinsのビルド失敗ログをAI分析ジョブに渡し、原因調査に役立つ要約を提供します。分析コード
- Mattermostのお知らせはサーバーに保存した後、コミット完了後にAIサービスへ要約、キーワード、対応の要否、期限の抽出を依頼します。分析結果はコールバックでお知らせの状態に反映します。お知らせ分析の処理

![WASSUBのMattermost通知](./assets/screenshots/wassub-notices.jpg)

*ローカルで起動した画面・お知らせの要約と対応要否の表示（デモ用データ）*

AIサービスは分析結果の生成を担い、Webhookの検証、権限確認、外部サービスへの書き込みはSpringサーバーが担当します。

## 4. 主な機能 — EC2の監視

チームのEC2にインストールするGoエージェントが、CPU、メモリ、ディスク、ネットワークの累積通信量、ロードアベレージ、稼働時間、Dockerコンテナ一覧、指定URLのヘルスチェック結果を収集します。エージェントはHTTPSでメトリクスを送信し、Springサーバーがトークンからワークスペースを特定して保存・取得します。画面ではこれらを可視化します。

インストールスクリプトはsystemdサービスを登録します。標準の収集間隔は60秒です。送信失敗時の再試行やバッファリングは実装範囲に含まれず、次の周期に新しいデータを送ります。エージェントの実装範囲

## 5. システム構成

| 構成要素 | 技術 | 役割 |
|---|---|---|
| Web | Next.js 16、React 19、TypeScript | ログイン、設定、ダッシュボード、詳細画面 |
| API | Java 21、Spring Boot 4.1 | 認証、ワークスペース、ツール連携、Webhook、SSE |
| AI | Python 3.12以降、FastAPI | MRレビュー、ビルドログ・お知らせの分析 |
| エージェント | Go、gopsutil | EC2のメトリクスとヘルスチェックの収集 |
| データストア | PostgreSQL、Redis | サービスデータ、AIジョブの状態、認証関連の一時データ |
| デプロイ | Docker Compose、Jenkins | サービスコンテナとCI/CD |

```text
ブラウザ（Next.js）
    ↕ REST / SSE
Spring Boot ── PostgreSQL・Redis
    ├─ GitLab・Jira・Notion API
    ├─ GitLab・Jenkins・MattermostのWebhookを受信
    ├─ FastAPI → LLMゲートウェイ
    └─ Goエージェント ← EC2のメトリクス
```

## 6. 設計上の課題と対応

| 課題 | 対応 |
|---|---|
| チームデータへのアクセス範囲 | 取得・変更時にワークスペースへの参加状態を確認し、接続・解除などの管理操作はOWNER権限に限定 |
| 外部サービスの認証情報 | GitLabの取得用トークンをワークスペース単位で管理し、Notionのトークンは暗号化して保存 |
| リアルタイムイベントの取りこぼし | SSEは変更通知に使い、取得APIと外部ツールの状態から画面を再構成 |
| 時間のかかるAI処理 | Webhookの受信・ジョブ受付とAI分析の完了を分け、結果をコールバックで反映 |
| EC2内のサービスへのアクセス | JenkinsからサービスサーバーへWebhookを送信し、EC2のメトリクスもエージェントが外部へ送信 |
